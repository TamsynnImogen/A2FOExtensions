# A2FOVideo v9 physical-frame presentation

V9 is installed in local Fleet Ops Roots. The user confirmed v8 movie playback
works, but provided a screenshot showing desktop on both sides of the picture.
Manual resolution acceptance is still pending.

## Evidence and limits

The [preserved v8 log](video-v8-resolution-2026-10-03.log) reports 1920x1080
borderless outer/client geometry at 0,0. The supplied 1920x1080 screenshot shows
a much narrower visible picture. The host's read-only xrandr query also reports
1920x1080. Those facts establish a discrepancy between reported HWND geometry
and visible coverage; they do not establish the cause or a DPI problem.

V8 retained one GetDC result for the whole movie and used unchecked visible
FillRect/StretchDIBits. A cached class/private DC can retain prior attributes;
[Microsoft GetDC](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdc)
documents that distinction. V8 also chose the VCL main form without comparing
the native movie-window getter. Neither retained state nor HWND mismatch was
recorded in its log, so their role in the live screenshot remains uncertain.

## Correction

The native Bink getter at FleetOpsHook RVA 1ddb94 is preferred when it returns a
visible, process-owned top-level window. Its getter prologue and cdecl contract
match the already supported ShellDisplay path and CRC-approved profiles.
Child HWNDs are excluded from that preference and rejected before any top-level
frame or screen-coordinate mutation. Main-form and largest-window fallback
remain available. No new child layout contract is assumed.

Modern video is composed into an owned full-client 32-bit DIB, including black
bars, then presented in a single visible blit. Each frame obtains a fresh
GetDCEx context with DCX_CACHE and DCX_CLIPSIBLINGS. [Microsoft GetDCEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdcex)
documents the cache flag's override of private/class DCs. Identity transform,
MM_TEXT and zero origins are applied under SaveDC/RestoreDC; application clip
state is cleared, while the system visible region and sibling occlusion remain.
Drawing, flush and state-restore failures are checked.

Diagnostics log the native getter, selected, main-form and foreground HWNDs,
class/styles and geometry. First-frame output diagnostics include WindowFromDC,
map mode, clip bounds, viewport/window origin and extents, source and destination.
The v8 input-release and audio-draining corrections are retained.

1920x1080 full frame, 800x600 black bars, 5x3 odd-size bars and 7x5 resize. A
1920x1080 target first filled white, then seeded with a 1200x675 viewport at
320,45, nonzero window origin, world translation and a small clipping region,
received fresh full-frame pixels. Prior mapping/transform/clip state was restored.
The initial odd-size fixture expectation was corrected to the actual 5x2 fit
with one black row; this was a test expectation error, not a runtime failure.

Native getter precedence, hidden/foreign/null/child fallback, zero child-geometry
mutations, draw failure paths, and existing geometry/input/audio fixtures passed.

the scoped source checks, DLL load/export smoke and headless tests. No game
