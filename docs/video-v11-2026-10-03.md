# A2FOVideo v11 performance pass

V11 is installed locally. The user reports v10 is essentially working, but has
low perceived FPS and a pause between every video, including native BIK movies.
The full-screen correction is user-accepted in that bounded sense; v11 live
performance and transition-pause diagnosis remain open.

## Supported formats

The dispatcher routes MP4, MKV and WebM extensions, and preserves native BIK.
Its embedded SDK has mov/MP4 and matroska/WebM demuxers. Registered software
video decoders are H.264, HEVC/H.265, VP8, VP9, MPEG-4 Part 2 and Theora.
Audio decoders include AAC, MP3, Opus, Vorbis, FLAC and PCM S16LE/S24LE/S32LE/F32LE.
AVI, WMV, standalone OGG and MOV extensions are not modern dispatcher routes.
Not every profile/container variation has been tested.

AV1 registration is not usable playback support here. The exact FFmpeg 9.0.2
source at .build/ffmpeg-win32/ffmpeg-9.0.2/libavcodec/av1dec.c requires a hardware
acceleration context or returns ENOSYS. Its generated configuration has all AV1
hardware backends and libdav1d disabled. The SDK enumeration confirms compiled
registrations; this source check excludes the unusable native AV1 decoder from
the working-format list. SDK source/archive identity is unchanged in this pass.

## Measured bottleneck and change

The [preserved v10 log](video-v10-performance-2026-10-03.log) labels the two
modern movies 30 and 29.97 fps; those are source rates, not achieved throughput.
A 120-frame headless benchmark against the actual embedded Win32 FFmpeg SDK
and the converted MadDoc source measured 18.425 fps. GDI HALFTONE composition
spent 5,932.803 ms (49.44 ms/frame), plus 297.247 ms of intermediate conversion.
That composition step alone exceeded a 30-fps frame budget.

V11 converts and scales the decoded AVFrame directly into the fitted part of
the owned top-down 32-bit DIB using libswscale. Full-client black clearing and
aspect-fit geometry remain. The intermediate source-sized BGRA allocation and
GDI StretchDIBits scaling are removed. [Microsoft's DIB guidance](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createdibsection)
calls for GDI synchronization before direct bitmap access; GdiFlush precedes
CPU writes. The previously checked physical GDI present, cached DC normalization,
window geometry and v10 event servicing are retained.

The same-SDK four-thread run measured 49.310 fps, with 2,209.068 ms composition
(18.41 ms/frame). Independent repeat measured 52.299 fps, with 17.28 ms/frame
composition. These are single headless throughput runs; they exclude live
window/compositor cost, audio and deliberate movie pacing. The source still
targets 30/29.97 fps. FFmpeg remains built without external x86 assembly; no
SDK rebuild was needed to remove the demonstrated GDI bottleneck.

## Startup and transition diagnostics

Automatic threading created 13 decoder threads on the local 12-thread CPU.
Video is now capped at min(4, CPU count), audio at one. The old path's first
presented frame measured 146.156 ms; direct composition with automatic threads
measured 96.091 ms, and with four threads 60.422 ms (independent 59.234 ms).
These startup times begin inside the probe executable and do not include Wine
process/library startup or live game window work.

An already-probed silent movie skips the redundant audio thread/file open.
Stream-info probing remains enabled for correctness; its old benchmark cost
was only 6.441 ms, insufficient evidence to blame it for a long transition pause.
New logs measure modern lookup, input open, probe, codec initialization, first
frame, paced rendered fps, composition/present costs, request duration, and gap
before the next request. The thread-local RAII boundary spans both native BIK
and modern playback; rejected recursion does not reset its outer timing.
A native occupied duration includes the whole native movie and any native
internal pause. It cannot isolate native first-frame latency. Gap also includes
previous boundary logging and outer caller work.

Because the user reports a pause between every movie, the native transition
path remains a separate live diagnostic question. Native BIK, shell module,
settings, game binaries and movie files are unchanged; the pause is not claimed
fixed by this performance change.
