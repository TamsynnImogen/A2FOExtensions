| Role | Files | Destination |
| --- | ---: | --- |
| Verified opaque tangent-space normal candidates, `*_bump.dds` | 180 | BC5 UNORM XY |
| Colour, alpha, emissive, UI or scalar data | 227 | BC7 UNORM RGBA |

Two SOD examples explicitly use the bump shader; all 180 candidates were also
CPU-inspected. They have opaque alpha and positive Z. BC5 consumers must explicitly
reconstruct positive Z and retain the existing Y convention. These are lossy
assets, not proof of per-material visual parity. Some original normal pixels
already differ from reconstructed unit vectors; the largest measured individual
base-mip angular difference was 33.68 degrees. Do not silently treat arbitrary
RG data as normals or automatically change colour space.

The source DDS files total 518,319,213 bytes, approximately 494.31 MiB; BC outputs
total 339,992,636 bytes, approximately 324.24 MiB. This is about
170.07 MiB less on disk, **not measured VRAM**. BC1 is 4 bits/pixel whereas BC5 and
BC7 are 8; the 199 BC1 source conversions grow by 85,462,880 logical payload bytes.
BC3 conversions have the same block rate. This pack tests coverage of the requested
formats; production optimisation should keep suitable compact BC1 assets.

## Conversion and supplied mips

`tools/build_bc_texture_mod.py` uses the already-installed Compressonator CLI
4.5.52, CPU encoding, quality 0.2, two BC7 threads. The external codec is not
vendored or a runtime dependency. The launcher and companion binary hashes are
in every receipt. No reference renderer or shader source was copied.

The codec rejects FO4's four L8 and 29 RGB16 files. Only those observed layouts
are expanded offline to BGRA8, preserving opaque luminance, RGB565 and ARGB1555
alpha semantics. All supplied levels are retained at their original dimensions.
There is no normal-channel swizzle, resampling or runtime RGBA fallback.

An actual authored-colour mip probe exposed that `-miplevels N` regenerates lower
mips instead of preserving them. The first 407-file output is therefore retained
only as an audit/base-level cache under `staged-mod`, and must never be deployed.
The corrected executor slices each original level, invokes `-nomipmap`, validates
the resulting single level, and assembles the chain. It reuses only a validated
base-level block payload from the old tree; it never reuses its lower levels.
New receipts require `mip_policy=preserve-supplied-v1`.
A five-level black/red/green/blue/white probe was extracted and independently
CPU-decoded level by level: all colours matched within one 8-bit channel level.
Receipts, codec logs and the proof are under
`build/renderer-bc-mod-20261021/`. Interruption between output and receipt commit
conservatively requires manual inspection; an unreceipted output is not overwritten.

## D3D8-facing resource bridge

`renderer/d3d8_compat/resources/compressed_texture8.*` exposes real
`IDirect3DTexture8` and implicit `IDirect3DSurface8` interfaces for immutable
external compressed assets. `renderer/d3d11/texture_handle.*` isolates modern SDK
headers and owns the typed D3D11 view. The facade retains one encoded CPU shadow
for read locks, not an expanded RGBA copy; the D3D11 upload remains compressed.

The facade implements COM identity, GetDevice/GetContainer, all supplied levels,
block-aligned read locks, shared surface/texture lock state, priority, LOD and
private data. Writable locks and dirty updates are deliberately refused for this
immutable asset type. It does not implement the game's mutable CreateTexture
path. A private binding interface supplies an AddRef'd SRV and explicit normal
interpretation/minimum LOD to a future compatibility device.

Implicit device binding references retain storage at public reference count zero;
GetTexture revives the canonical interface. Public references retain the owning
device. This avoids a future device/texture COM cycle. Destruction and binding
transitions belong on the device owner thread, the module must remain loaded,
and the eventual sampler consumer must honour minimum LOD. It is unsafe to pass
these facades to an existing native provider's SetTexture. The fixture uses a
native D3D8 device only for identity/reference semantics, never to draw a facade.

Real ATI2 DDS output uses an unused depth field of one. The parser accepts this
for undeclared 2D input while continuing to reject volume declarations and depth
greater than one. CPU tests cover both cases.

## Runtime gates and comparison

No unsupported `Backend=d3d11` setting is enabled. The system/dxvk selection in
existing graphics options concerns the legacy path. The full D3D11 factory,
device, mutable buffers/textures, state blocks, fixed-function combinations,
actual shaders, render targets, Reset/lost-device and presentation remain required
before FO can use this pack. The brief triangle shown earlier was a device/window
probe, not a complete game renderer. A candidate core DLL is staged separately;
installed startup, renderer modules and the minimap fix are preserved.

After those gates, manually compare FO4 / child / FO4 using the same map, faction,
ship count, camera, settings, resolution and simulation time. Separate cold/warm
runs and test UI/minimap, all factions, particles, shields, transparency and normal
materials. Restart between mods. Roll back by selecting Fleet Ops 4.0 and restarting.

`tools/monitor_bc_comparison.py` supplies a read-only manual-run sampler:

```sh
python3 tools/monitor_bc_comparison.py --label fo4-baseline --seconds 120 --output build/renderer-bc-mod-20261021/fo4-baseline.jsonl
python3 tools/monitor_bc_comparison.py --label fo4-bc-test --seconds 120 --output build/renderer-bc-mod-20261021/fo4-bc-test.jsonl
```

It discovers only a unique Armada2.exe/ArmadaL.exe process (or an explicit verified
PID), samples process CPU/RSS/PSS/I/O and whole-NVIDIA-GPU usage, and never launches,
stops or controls the game. Whole-GPU usage is not per-process VRAM and the Intel
adapter used by headless fixtures is outside NVIDIA telemetry. It measures no FPS
or texture residency. Labels are supplied context, not verification of active mod.
No live game telemetry or in-game visual acceptance has been collected yet.

## Validation and deployment result

The corrected build completed **407/407, zero failures**. Every output retained
its original dimensions and supplied mip count, passed strict header/block-extent
validation and matched its receipt hash. All 407 reused only verified top blocks;
lower levels were encoded from their original supplied level. All 407 parent
source hashes still match. The first-pass tree remains separate and undeployed.

On Intel UHD Graphics 630 (8086:3e9b) under Wine in a private headless compositor:

- CPU DDS validation passes, including the ATI2 unused-depth-field case.
- BC5 UNORM/SNORM and BC7 UNORM/sRGB pass 24 synthetic format/mip/mode pixel
  comparisons, plus a compressed texture draw through the modern UI backend.
  These views come through the new D3D8 texture facade.
- Facade contracts pass for identity, implicit surface persistence, private-data
  object references, encoded read locks, shared locking, LOD and bound storage
  revival/unbinding. Null-buffer private-data queries match a native D3D8 texture.

  `all_interface_buttons03.dds` (BC7, one mip) pass all 256 sparse base-level
  reference bytes with maximum delta zero. Their base blocks match the independent
  CPU-decoded reference input exactly; these sparse checks do not assess complete
  image quality. Synthetic samples cover lower-mip sampling.
- All **407 final DDS files** create typed immutable D3D11 textures and matching
  full-mip SRVs. Their aggregate logical compressed payload is **339,936,000 B**.
  This test allocates and releases files sequentially; it is not a live scene,

- Strict GPU fixture compilation and the updated core link pass. The core imports
  no mandatory D3D11/DXGI/compiler DLL. Existing unrelated core warnings remain.
  Candidate: `build/renderer-bc-mod-20261021/candidate/A2FOExtensions.dll`;
