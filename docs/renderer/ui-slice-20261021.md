# D3D11 transformed-vertex rendering slice

The next migration slice renders D3D8-style transformed UI geometry through
original SM5 shaders on D3D11. This is a real draw/texture/state backend and a
pixel comparison milestone, **not a complete D3D8 COM implementation or D3D11
game renderer**. Normal installed gameplay remains on its current D3D8 path.

The native Fleet Operations traces now populate 74 of the 225 method rows in
`compatibility-matrix.csv`. Stock Armada II observations remain unknown; FO
Classic mods are not relabelled as stock Armada observations. Capped trace
absence never establishes non-use. Observed FVFs include `0x44`, `0x144`,
`0x1c4`, and untransformed `0x112`, plus programmable shader handles. Observed
resources include ARGB/XRGB8888, RGB565, L8, DXT1 and DXT5. Programmable shaders
and state blocks remain mandatory future compatibility work.

## Implemented boundaries

| Module | Responsibility |
| --- | --- |
| `renderer/state/fvf.*` | FVF layout validation, texture-coordinate dimensions, checked primitive counts and fan-to-triangle index expansion |
| `renderer/textures/upload.*` | Pitch/span-checked RGBA8 conversion from ARGB/XRGB8888, RGB565 and L8; BC1/2/3 block uploads from DXT1/3/5, one mip at a time |
| `renderer/shaders/bytecode_cache.*` | Dynamic D3DCompile loading, compiled bytecode persistence, full-key/integrity checks and corrupt-cache recompilation |
| `renderer/shaders/ui_fixed_function.hpp` | Original SM5 transformed-vertex and single-stage fixed-function shader source |
| `renderer/d3d11/ui_renderer.*` | Explicit UI draw state, D3D11 resource/state ownership, retained dynamic UP buffers, indexed fans and viewport-clipped colour clears |
| existing probe/observer | Startup-gated factory seam and one-frame native-HWND diagnostic; normal legacy fallback retained |

Neutral FVF/texture headers carry numeric D3D8 values without including the
legacy COM SDK. D3D8 and D3D11 implementation translation units stay separate:
this MinGW SDK otherwise redefines `D3DCOLORVALUE`. No COM pointer casts or
layout renaming workarounds bridge the SDKs.

The draw slice admits XYZRHW with optional diffuse/specular and one float2 UV.
It supports a defined single-stage subset (disable/select/modulate/add,
diffuse/current/texture arguments, complement/alpha-replicate), alpha testing,
blend factors/operations, depth test/write, culling and colour masks. It rejects
untransformed/normal-bearing layouts, multiple UV sets, unsupported combiners,
missing required textures, invalid spans/indices, oversize vertex strides and
texture aliases with either colour or depth output. The compatibility facade
must supply and validate the complete legacy state before choosing this slice;
unmodelled game states must not be silently ignored.

The legacy pixel-centre convention is explicitly translated in the vertex
shader, including reciprocal-W interpolation. Microsoft documents the
[D3D9/D3D10 coordinate difference](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-coordinates).
Clears draw clipped screen rectangles because a full-target D3D11 clear would
not reproduce the minimap's D3D8 rectangle/viewport semantics. Depth/stencil
Clear translation is still pending. Only viewport depth range 0..1 is admitted
by this slice.

Shader keys include source, entry, profile, flags and compiler path/size/mtime.
Reads compare the full key, bounded file lengths, payload hash and DXBC marker.
Invalid or unreadable caches recompile; cache-write failure does not invalidate
valid compiled output. Writes use a private temporary file and atomic replace.
The probe stores bytecode under `%LOCALAPPDATA%\A2FOExtensions\ShaderCache`,
using the temporary directory if that environment variable is unavailable.
If cache-directory creation fails it compiles without persistence. No compiler
or D3D11 DLL becomes a mandatory core import. No background compilation or new
unfinished graphics options are exposed.

Device/context use, shutdown and destruction are serialized by the owner thread.
The renderer retains its COM references and owns its pipeline state; it is not
an overlay that preserves an unrelated D3D11 context. Reinitialization from a
different thread rejects before destroying the active renderer.

No reference-project implementation or Microsoft sample HLSL was copied. The
fixed-function shader and conversion/cache code here are new implementations;
the earlier reference licensing audit remains relevant for future reuse.

## Evidence and reproduction

`make renderer-compat-tests renderer-modernisation-tests build/A2FOExtensions.dll`
builds the helpers, paired GPU fixture, updated shared-HWND probe fixtures and
core. The new test targets compile with warnings treated as errors; the complete
core retains existing warnings in unrelated menu/renderer code.

`tools/run_renderer_validation.py --fixture compat` runs FVF/fan, texture-span
and shader-cache tests in the dedicated Wine prefix. `--fixture ui` runs the
paired pixel fixture under a private headless compositor. Add `--wrapper-root`
to stage read-only copies of an existing D3D8/dxwrapper/DXVK chain. Do not use a
game executable as a fixture host or automate the desktop.

Nineteen paired scenes cover diffuse/indexed fans, alpha blending/testing,
texture point/linear/select/add operations, luminance/RGB565/BC1/BC2/BC3,
specular colour, write masks, clockwise/counterclockwise culling, viewport
draws and viewport-clipped Clear rectangles. Comparisons include every RGB
pixel, including edges; differences over one 8-bit level fail. RGB565 expansion
can differ by one level from native normalized sampling. These are synthetic
scenes, not game screenshots, fonts, or whole UI acceptance.

Fixtures also check unsupported state/layout/stride rejection, depth/texture
alias rejection, owner-thread reinitialization, shader cache hits/key changes/
corruption recovery, and retained observer identity/state/reset contracts.
The one-frame `d3d11-probe` now presents an SM5 gradient triangle, then releases
its temporary D3D11 device and resumes native D3D8. It does not replay a captured
game draw or imply whole-frame translation. Exclusive mode remains excluded.

Evidence is under `build/renderer-ui-slice-20261021/`: helper receipts,
`pixels-final-builtin`, `pixels-final-managed`, probe/provider receipts and
paired PPM image artifacts. The wrapper sources are the preserved predeployment
payloads, not an assumed active runtime chain. Successful game minimap evidence
and the corrected ShellDisplay deployment remain separately recorded in
`minimap-shared-uv-fix-20261021.md`.

## Next compatibility gates

1. Capture declarations, shader tokens and relevant state transitions for the
   proven native/FO programmable-shader paths. Pointer-only logs cannot establish
   shader instructions, constant values or resource contents.
2. Add checked legacy VB/IB/texture resource identity and Lock/Unlock update
   semantics, state-block recording/apply/capture and Reset lifetimes. Route
   native fan and indexed-list submissions through the backend without changing
   the game's render order.
3. Extend the fixed-function/programmable paths for XYZ transforms, lighting,
   multiple texture stages, fog and the actually used shader combinations.
4. Admit a full game frame only when all its calls/resources/states are covered;
   unsupported work must retain a usable legacy fallback, not disappear with
   S_OK. Then perform the requested menus/editor/factions/effects comparisons.

The working install is not switched to D3D11 by these builds. Full `Backend=d3d11`
remains refused. Refit's independent D3D9 menu scene, videos, VCL/GDI tools and
native presentation ownership have not been replaced.
