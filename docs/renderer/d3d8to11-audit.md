# d3d8to11 reference audit

Read-only source review of `michael-fadely/d3d8to11`, checkout `/tmp/a2fo-d3d8to11-reference`, commit `d4b2c6c5d7d1ec3b96881476c83637efed598514` (shallow checkout; commit date 2025-04-09). No build or runtime validation was performed. The accompanying CSV inventories the API methods found in the base, device, and resource implementation files; statuses are source inspection classifications, not compatibility claims for Armada.

## Architecture and comparison with Refit

The project describes itself as a shim emulating the DirectX 8 fixed-function pipeline on DirectX 11 (`README.md:3-4`). It exposes D3D8 interfaces through wrappers and creates a hardware D3D11 device plus swap chain (`d3d8to11/d3d8to11_device.cpp:771-775`). Device state is translated into D3D11 resources, state objects, shaders, and draw calls. This is a broad API compatibility layer, rather than a host-controlled renderer entry point.

The local Refit renderer has two relevant architectures. Its upstream game renderer enters at two `Armada_RenderAllOurStuff` call sites, preserves the stock body for steps not replaced, and manages per-device frame targets/reset (`third_party/armada2-refit/menu-renderer/src/frame/mod.rs:1-9,21-67`). Its menu-only host adaptation has an explicit versioned ABI and borrowed D3D9 device, ordered asset roots, and owner-thread requirement (`src/host.rs:19-32,42-79`); the host build disables executable hooks, engine memory access, and sound, and registers World/Hulls/Sky only (`SOURCE.md`, `menu-renderer/LOCAL-CHANGES.md`, `src/mods/mod.rs:116-148`). World subsystem state is held in `World`; reset drops surface, planet, rock and nebula GPU caches (`src/mods/world/mod.rs:28-40,143-150`). The SOD scene cache is a keyed `BTreeMap` of models and reset clears models, queue and device (`src/scene/mod.rs:74-79,220-232`). These are concrete, existing integration seams; they do not establish which D3D8 calls Armada makes.

## d3d8to11 unsupported and partial behavior

The complete method-level inventory is in `d3d8to11-method-status.csv`. `NOT_IMPLEMENTED_RETURN` logs and returns `D3DERR_INVALIDCALL`; `NOT_IMPLEMENTED` only logs (`d3d8to11/not_implemented.h:6-17`). Notable gaps include additional swap chains, volume/cube textures, render-target and depth-stencil surface creation, state blocks, palette APIs, vertex shader object APIs, all pixel shader APIs, and patch APIs. Triangle-fan indexed draws log but return success without drawing (`d3d8to11/d3d8to11_device.cpp:3255-3265`). `GetAvailableTextureMem` logs and returns `UINT_MAX` (`1174-1181`). D3D adapter reporting has fake-success paths: identifier is zero-filled (`d3d8to11_base.cpp:138-148`), format checking accepts most cases (`236-257`), and depth-stencil matching returns success (`267-271`).

HLSL texture operations `PREMODULATE`, `BUMPENVMAP`, `BUMPENVMAPLUMINANCE`, and `DOTPRODUCT3` return a red diagnostic result (`d3d8to11/d3d8to11.hlsl:594-624`). Camera-space position/reflection texgen and projected texture coordinates are TODOs (`709-715,808`). Additional sampler TODOs leave MinLOD/MaxLOD at extremes and bias zero instead of translating render-state values (`d3d8to11_device.cpp:4185-4230`, assignments at 4212-4214). Capability reporting is hard-coded and explicitly omits several texture caps (`d3d8to11_base.cpp:274-288,393-395`).

Reset handles size/windowed changes by unbinding, resizing swap-chain buffers, and recreating depth/back-buffer resources; device-lost handling and fullscreen toggle remain TODO (`d3d8to11_device.cpp:1299-1307,1332-1359`). Present copies the render target to the back buffer and presents (`1449-1486`). It also polls `GetAsyncKeyState` for Ctrl+O OIT toggling and Ctrl+R shader-cache commands (`1488-1512`). Those runtime input hooks and the OIT subsystem are not suitable code to transplant into an Armada integration without an independently authorized design; no Armada call usage is inferred here.

## Resources, locking, shader cache, and notices

Vertex and index buffers use D3D11 buffers and CPU-side lock staging; see `d3d8to11_vertex_buffer.cpp:10-36,125-178` and `d3d8to11_index_buffer.cpp:10-36,125-178`. Texture locking tracks locked rectangles and uploads on unlock (`d3d8to11_texture.cpp:340-426`). The source has a TODO to make render-target texture data CPU-accessible (`texture.cpp:383-389`); lock paths reject invalid combinations/ranges, but this audit did not establish thread-safety or race-freedom. Treat concurrent locking/resource access as unknown. Cube and volume texture implementations are under disabled `#if 0` blocks (`texture.cpp:599-601,771-773`).

Shader variants are keyed/cached by translated flags and compiled from HLSL; device methods `get_shaders`, `update_shaders`, and `free_shaders` are in `d3d8to11_device.cpp:4235-4300,4479-4532`. It already persists permutation flags (`309-420,852-999`) and recompiles previously seen variants at startup using its thread pool. This is not persistent compiled bytecode: `compile_vertex_shader` and `compile_pixel_shader` invoke `D3DCompile` on source. Present's Ctrl+R path clears/reloads cached shaders (`1488-1512`). Fixed-function stage state is translated through a sizeable HLSL implementation; unsupported stage operations and texgen are called out above. There is no evidence here of suitability for Refit's model/asset caches; the two systems cache different objects for different responsibilities.

The upstream `LICENSE` is MIT, copyright Michael Fadely 2018 (`LICENSE:1-21`). Multiple implementation files explicitly carry Patrick Mours 2015 copyright and point to `crosire/d3d8to9#license` (for example `d3d8to11/d3d8to11_device.cpp:2-3`, `d3d8to11/d3d8to11_texture.cpp:2-3`, and `d3d8to11/d3d8to11.cpp:2-3`). The lead separately verified the linked project's current [BSD 2-clause licence](https://github.com/crosire/d3d8to9/blob/main/LICENSE.md), copyright Patrick Mours 2015. Derived source and binary redistributions require its notices/disclaimer as well as the d3d8to11 MIT attribution. `include.hlsli:59` and `d3d8to11.hlsl:232` contain Microsoft 2005 `FixedFuncEMU.fx` copyright notices; the original applicable sample terms remain unresolved before direct HLSL reuse. No upstream implementation/HLSL code is copied into this milestone. This is not a complete transitive licence audit.

State enum handling is selective, not a complete mapping claim: `SetRenderState` and `GetRenderState` have explicit ignored/invalid cases (`d3d8to11_device.cpp:2266-2290,2648-2679`); texture-stage getters/setters enumerate handled states and the getter comments out `D3DTSS_BORDERCOLOR` (`2792-2887,2889-3033`). Format/primitive conversions live in `d3d8to11.cpp` and `d3d8types.cpp`; unsupported/default branches map to `UNKNOWN`/`UNDEFINED` or are rejected at the call site. See per-method status rows and inspect converter switches before any format-specific port decision.

## Source and assumptions

Commands used included `git rev-parse HEAD`, `rg -n` over implementation/HLSL sources, and line-numbered inspection with `nl -ba`. The CSV is generated from the implementation definitions in the base/device/resource `.cpp` files and classifies direct stubs, explicit fake-success/partial paths, and remaining methods as implemented-at-source-level. “Implemented” means a non-stub body exists, not that D3D8 semantics are complete or correct. The full D3D8 API contract, transitive licences, actual Armada call graph, and runtime behavior remain unverified.
