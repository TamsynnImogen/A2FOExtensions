## Route and resource handling

In `renderer/d3d8_compat/observer.cpp`, the child setting arms the named
`Direct3DCreate8` import bridge. The original D3D8 factory remains available for
adapter/display queries; its native D3D8 device is bypassed. `Factory::CreateDevice`
returns the `IDirect3DDevice8` compatibility facade, whose translated draws,
resources and presentation use `renderer/d3d11/game/backend.cpp`.

With `BCTextures=1`, startup requires the opt-in named `fopen` IAT bridge for
catalogued loads. Private per-asset DXT4-header transport files let the legacy
DDS parser carry the encoded block bytes. The BC path matches the loaded bytes
against the catalog, then uploads the canonical compressed blocks; it does not
decode/re-encode them or edit canonical DDS files. `bc_catalog.cpp` verifies the
canonical file hash, dimensions, format, mip count, exact payload extent, top
mip hash and every mip hash before accepting an asset. `normal_xy` is explicit
catalog metadata; the shader path reconstructs positive Z for those BC5 assets.

The catalog has exactly 407 entries. A missing/invalid catalog or incomplete
required bridge fails the child closed. `BCTextures=0` uses the ordinary mutable
texture conversion path and does not install the BC file bridge. The D3D11
shader cache persists across game restarts at
`Data\A2FOShaderCache\d3d11-test`; record whether each run is cold or warm.

## Current limits

`renderer/d3d8_compat/game/unsupported.cpp` explicitly rejects these device
methods: `SetCursorProperties`, `SetCursorPosition`, `ShowCursor`,
`CreateAdditionalSwapChain`, `GetRasterStatus`, `SetGammaRamp`, `GetGammaRamp`,
`CreateVolumeTexture`, `CreateCubeTexture`, `GetInfo`, `SetPaletteEntries`,
`GetPaletteEntries`, `SetCurrentTexturePalette`, `GetCurrentTexturePalette`,
`ProcessVertices`, `CreatePixelShader`, `DeletePixelShader`,
`SetPixelShaderConstant`, `GetPixelShaderConstant`, `GetPixelShaderFunction`,
`DrawRectPatch`, `DrawTriPatch` and `DeletePatch`. Nonzero `SetPixelShader` is
also unsupported. Cube and volume textures and pixel shaders are therefore not
implemented in this experiment.

`CreateStateBlock` accepts only `D3DSBT_ALL`; typed `PIXEL` and `VERTEX`
snapshots are unsupported. `BeginStateBlock`/`EndStateBlock` record only the
state setters represented by the facade's recording mask. `GetFrontBuffer` is
explicitly unsupported; it does not capture the backbuffer. Vertex shader
translation is the deliberately bounded nine-opcode VS1.1 subset in
`renderer/shaders/vs11.cpp`: MOV, ADD, MAD, MUL, RSQ, DP3, MIN, MAX and M4X4.
It is not a general VS1.1 translator and there is no pixel-shader translation.
The backend maps requested D16/D16_LOCKABLE to D16, D24S8/D24X8 to D24S8, and
D32 to D32. If automatic depth/stencil is disabled, it creates no depth
target. These mappings do not imply complete D3D8 depth/stencil parity.

The extension's DXVK-specific material and bloom effects are suspended in both
experimental children. Normal FO4 runs keep their existing behavior. Differences
in those effects should not be attributed to the BC texture child.
