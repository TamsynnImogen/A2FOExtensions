# Captured vertex programs through SM5

This slice translates three **actual captured A2FO vertex programs** to SM5 and
compares their rendered pixels with the original D3D8 programs. It is a tested
shader component, not an enabled D3D11 game renderer. Device/resource ownership,
shader handles, state blocks and full-frame presentation still use the existing
legacy path in the installed game.

## Implementation boundary

`renderer/shaders/vs11.*` implements original bounded decoding and HLSL generation
for the nine observed opcode families. It preserves source negation/swizzles,
destination masks and read-before-write behavior. It checks register ranges,
initialized temporary channels, matrix register spans and complete position
output. Unsupported versions/instructions, relative addressing, address/fog/
point-size outputs, other source/destination modifiers and uncaptured matrix-vector
modifiers are explicitly refused. Failure clears the output and identifies the
word offset. This is not complete VS 1.1 validation or a COM shader API.

Only used input registers enter the shader signature. The caller must supply
converted declaration attributes with legacy component defaults, as the fixture
does for FLOAT2/FLOAT3. Constants use b0 (`float4[96]`); b1 contains inverse
viewport dimensions. Position receives the legacy pixel-centre correction.
Colours are clamped at vertex output. `precise` intermediates avoid unnecessary
arithmetic contraction. Unwritten outputs are initialized deterministically,
but **only channels in `output_masks` are established legacy outputs**; a future
pixel/state facade must reject reliance on unwritten channels.

`vs11_output_interface()` supplies the shared vertex-output/pixel-input structure.
Both shader stages must use it to keep D3D11 signature registers consistent.
Assembler comments do not enter generated source, so irrelevant comment changes
do not cause recompilation. The existing persistent DXBC cache remains the
compiler boundary; changed constants or viewport dimensions are constant-buffer
updates, not new shader permutations.

The checked-in fixture payloads contain these known A2FO-produced programs,
including their trace provenance. No Refit/d3d8to11 implementation or Microsoft
sample shader was copied. Semantics were checked against the SDK and Microsoft's
[RSQ](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/rsq---vs),
[M4x4](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/m4x4---vs), and
[register](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx9-graphics-reference-asm-vs-registers-vs-1-1)
references. The M4x4 reference contradicts itself about source modifiers; this
slice admits only the unmodified form actually captured.

## Validation

`make renderer-vs11-tests build/A2FOExtensions.dll` builds the shader component,
CPU checks, paired GPU fixture and integrated core. New fixture targets use
`-Werror`; the core retains pre-existing warnings elsewhere. No mandatory D3D11,
DXGI or shader-compiler import was introduced.

The CPU checks cover the three captured programs, every truncated prefix,
comment-independent source keys, sparse/zero input signatures, temporary-channel
dependencies, bounds and explicit unsupported-state refusals. They pass under
both host C++ and the 32-bit Wine console fixture.

Six scenes use the original 68-byte vertices and controlled constants, changing
lighting, ambient colour, fade, tangent bases, clip-space W and viewport offsets.
All RGB pixels, including edges, are compared with tolerance one; reference
coverage is required so an empty render cannot pass.

| Reference provider | Samples | Result |
| --- | --- | --- |
| Wine D3D8 | 1 | All six scenes exact RGB agreement |
| Preserved dxwrapper/DXVK chain | 8 | All six scenes within one 8-bit colour level |

The preserved wrapper forces antialiasing. The fixture queries its actual render
target sample count and creates/resolves a matching D3D11 target; installed and
staged wrapper settings were not changed. This is fixture support, not a new
product MSAA setting or validated D3D11 swap-chain mode.

Constant-only variants hit the bytecode cache without compilation. A fresh
process also reuses all three cached programs with `compile_us=0`. Initial cold
compilation in the earlier built-in run took approximately 30/32/51 ms for the
13/21/39-instruction programs; these fixture timings do not measure game startup.

Final receipts and paired PPM images are under
`build/renderer-vs11-slice-20261021/builtin-final/`, `managed-final/`, and
`cpu-final/`. Earlier input-signature, pixel-signature and mismatched-sample
failures remain preserved; their assertions were corrected without relaxing
the final all-pixel tolerance. The final manifest records exact artifact hashes.
