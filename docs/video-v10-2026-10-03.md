# A2FOVideo v10 window event service

V10 is installed in local Fleet Ops Roots. This is a bounded correction to a
missing UI event-service path, with live screen-coverage acceptance still pending.

## Live evidence

The user's v9 screenshot still shows desktop on both sides of the movie. The
[preserved log](video-v9-resolution-2026-10-03.log) reports the same native/main/
foreground TMainWindowForm, 1920x1080 outer/client dimensions at 0,0, and a full
1920x1080 output DC clip with identity pixel mapping. V9 did not fix the live
issue; those rectangles do not establish Wine compositor coverage.

Source inspection found that the modern decoder blocks through frame pacing
and audio-tail waiting without processing window messages. Upstream Wine's
[X11 event handler](https://github.com/wine-mirror/wine/blob/master/dlls/winex11.drv/event.c)
posts internal window-state changes, and its
[Win32 message handler](https://github.com/wine-mirror/wine/blob/master/dlls/win32u/message.c)
can apply the updated host rectangle with NtUserSetWindowPos. Queue starvation
is therefore a plausible mechanism, not a proven explanation of this screenshot.
The exact local PROTON_LG_10-28 source was not matched to those upstream files.
The runner environment enables WINE_FULLSCREEN_FSR=1; no direct causal link
between that setting and this GDI failure was established. Runner settings are
unchanged. ShellDisplay patches only Armada/FleetOps imports, not this module's
GDI imports; no repository window-shaping path was found in the scoped search.

## Correction and limits

MovieWindowEvents polls sent/internal layout events and dispatches at most 64
posted paints per poll, before each new frame and throughout frame pacing.
Client input, timer and command messages remain queued for the native loop.
Posted close is observed thread-wide without removal; close/quit or a destroyed
playback HWND cancels and returns handled even before the first frame, avoiding
native fallback during shutdown. Removed quit is reposted with its exit code.

[PeekMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-peekmessagea)
can dispatch sent messages even with a filter. A same-thread RAII guard prevents
nested movie playback, and the HWND is validated after queue service and paints.
During the audio tail, posted paints stay queued so they do not overwrite the
last frame. Existing geometry, pixel composition, aspect fitting, audio drain
and release-then-fresh-press skipping are retained to isolate this change.

The full client frame includes black margins. A 1280x720 source in a 1920x1080
client should fill the client; a 4:3 source in that client has 240-pixel black
side margins. New diagnostics record post-service HWND geometry, device origin,
selected bitmap size when available, and display/desktop device caps. These
still describe Win32 state rather than proving host compositor coverage.

64-paint bounds, retained game messages and tail paints, close on a different
HWND, quit-code preservation, destruction and sticky cancellation. A real
interception callback recursively requests a movie: reentry is rejected and a
later outer call succeeds. These queues and callbacks are synthetic.

black side bars for a narrower movie, top/bottom bars, odd sizes, resizing and
stale output transforms/clipping with restored state. AAC/Opus/Vorbis/short AAC
and the converted MadDoc fixture passed PCM duration and drain checks; MadDoc
