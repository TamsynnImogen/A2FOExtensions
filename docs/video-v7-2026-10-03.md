# A2FOVideo v7 local correction

Installed A2FOVideo v7 and a sound-bearing MadDocSoftware MP4 replacement in
the local Fleet Ops Roots test mod. Manual client acceptance is pending.

## Findings

The preserved v6 log selected 1920x1080 borderless and reported an actual
1920x1080 client in that run. It does not reproduce every reported geometry
failure. Source inspection found that modern playback never applied the saved
mode: preceding native Bink playback happened to resize the window in this run.
Modern playback also selected a window by largest area rather than main-form
identity. V7 applies saved geometry before drawing and prefers the verified
main VCL form, so a modern first movie does not depend on native Bink playback.

The exact original `/home/tamsynn/Games/st legacy/animations/intro.bik` has only
a Bink video stream. The existing test-mod `intro.mp4` is also video-only.
`MadDocSoftware.bik` in the same source directory contains 1280x720 Bink video
and mono 22050 Hz Bink audio. Its MP4 replacement contains H.264 and mono
22050 Hz AAC; runtime output is stereo 48000 Hz S16.

V7 sets up resampling from the first decoded audio frame, flushes delayed
samples, and waits for queued buffers at natural EOF. Skips/errors cancel.
The former audio-thread destructor called waveOutReset without draining, which
can discard queued sound; see [Microsoft waveOutReset](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutreset).
Resampler flushing follows [FFmpeg libswresample](https://ffmpeg.org/doxygen/trunk/group__lswr.html).
Absent-stream diagnostics are now distinct from unavailable decoder failures.

## Scope and validation

Only A2FOVideo source/bridge, its build/test target, new headless test fixtures,
and video documentation were changed. Existing unrelated working-tree changes
were preserved. The DLL's settings/form offsets are limited to the three
whole-file FleetOpsHook profiles already supported by ShellDisplay. The
installed profile is 3043840 bytes, CRC32 46a0dd96. Movie entry ownership,
Armada identity and prologue checks remain enabled.

Window checks use synthetic USER32/VCL hosts and cover selected 1600x900
borderless size, framed outer centring, desktop resolution, secondary negative
monitor origin, oversized title-bar accessibility, native-form precedence,
invalid settings and nested-state bypass. No focus or activation is requested.

Both commands passed:

```bash
make video CXXFLAGS='-std=gnu++17 -O2 -Wall -Wextra -Wpedantic -Werror -DNDEBUG'
make video-test VIDEO_REFERENCE_MOVIE=build/video-fixtures/MadDocSoftware.mp4
```

The test captures non-silent PCM from the actual embedded Windows libav backend
with fake WinMM output: AAC 67208 bytes, Opus 67200, Vorbis 67208, short AAC
11520, and MadDocSoftware 7907712. Natural drain, cancellation and device/open/
prepare/write failures passed. Portable `make video-test` also passed using a
synthetic 3-second AAC reference (576000 bytes), with no proprietary dependency.
FFmpeg emitted timestamp-discard notices for some decoder padding; all duration
and non-silence assertions passed.

An independent review passed the source/build checks and real DLL
LoadLibrary/GetProcAddress smoke without running ModuleInit or game startup.
No input-device automation, window creation or audible test output was used.
